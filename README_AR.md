# مشروع تطبيق فندق ومطعم حرض الدولي — نسخة تأسيسية

المشروع يحتوي على تطبيق Android أصلي بسيط يعرض واجهات محلية مضمّنة داخل APK، وواجهة طلب مطعم/حجز غرفة/شكاوى/دخول إدارة، وملف SQL لقاعدة Supabase، وGitHub Actions لبناء APK سحابيًا.

## مهم قبل الاستخدام الفعلي
هذه نسخة تأسيسية وليست نظامًا إنتاجيًا مكتملًا. نموذج الإدارة يعرض القوائم، لكن إجراءات تحديث حالة السجلات وإدارة الغرف/القائمة/الموظفين والعملات تحتاج استكمالًا واختبارًا. راجع سياسات RLS مع مختص قبل إدخال بيانات حقيقية. طلبات العملاء العامة قابلة للإرسال المجهول؛ أضف حماية من الإساءة/معدل الطلبات والتحقق عبر الخادم قبل الإنتاج.

## الجزء الأول: إعداد قاعدة البيانات (Supabase)
1. افتح https://supabase.com وأنشئ حسابًا ومشروعًا جديدًا.
2. اختر كلمة مرور قوية لقاعدة البيانات واحفظها بمكان آمن.
3. من لوحة المشروع افتح SQL Editor.
4. افتح الملف `supabase/schema.sql` وانسخ محتواه كاملًا إلى SQL Editor ثم اضغط Run.
5. من Project Settings / API أو Connect انسخ Project URL وPublishable key (أو anon key القديم).
6. افتح `app/src/main/assets/www/app-config.js` واستبدل القيمتين:
   - `https://YOUR_PROJECT_REF.supabase.co`
   - `YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY`
   لا تضع service_role أو secret key داخل التطبيق أبدًا.
7. في Supabase > Authentication أنشئ مستخدمًا للمالك من لوحة المستخدمين (لا تفتح التسجيل العام للموظفين دون سياسة واضحة).
8. انسخ UUID الخاص بمستخدم المالك من Authentication > Users، ثم نفّذ في SQL Editor مع استبدال UUID والاسم:
   `insert into public.profiles (id, display_name, role) values ('UUID-HERE', 'مالك الفندق', 'owner');`
9. أنشئ حسابات الموظفين من لوحة Auth ثم أضف UUID لكل مستخدم إلى `profiles` بدور مناسب: manager أو reception أو cashier أو kitchen.
10. اختبر بحسابات تجريبية قبل إدخال بيانات حقيقية. راجع كل سياسات RLS وتأكد من أنها تحقق فصل الصلاحيات المطلوب.

## الجزء الثاني: بناء APK من الهاتف فقط باستخدام GitHub
1. افتح https://github.com من متصفح الهاتف وأنشئ حسابًا أو سجّل الدخول.
2. أنشئ مستودعًا جديدًا باسم `haradh-hotel-app` واجعله Private.
3. ارفع محتويات هذا المشروع إلى المستودع مع الحفاظ على مسارات الملفات والمجلد `.github/workflows/build-apk.yml`. يمكن رفع ZIP وفكّه محليًا على الهاتف ثم رفع الملفات عبر واجهة GitHub؛ لا ترفع ملف ZIP وحده.
4. افتح تبويب Actions داخل المستودع وفعّل Actions إذا طُلب ذلك.
5. اختر سير العمل `Build Android APK` ثم اضغط `Run workflow`، أو ادفع commit جديدًا إلى main.
6. انتظر حتى يظهر التشغيل باللون الأخضر، وافتح التشغيل ثم قسم Artifacts وحمّل `HaradhHotel-debug-apk`.
7. فك ضغط artifact على الهاتف، ثم افتح `app-debug.apk` وثبّته. قد يطلب Android السماح بالتثبيت من هذا المصدر.

## ملاحظات
- تحتاج الإنترنت حتى تعمل الطلبات والحجوزات وقاعدة البيانات.
- البناء الناتج Debug APK للتجربة، وليس إصدارًا موقّعًا للنشر التجاري.
- GitHub Actions يحتاج حسابًا وصلاحية Actions في المستودع؛ قد تنطبق حدود استخدام/دقائق بحسب الحساب.
- تغيير إعدادات `app-config.js` يتطلب إعادة بناء APK.
- العملة قابلة للاختيار في نموذج الطلب، لكن إدارة العملة من لوحة الإدارة تحتاج استكمالًا.
- لا تخزّن مفاتيح سرية أو كلمات مرور في ملفات التطبيق أو GitHub.
